## Procedure
- Define the metric, the workload, the environment and the condition that makes a result correct before you compare anything.
- Keep the build profile, inputs, machine and settings the same between runs you compare.
- Take more than one sample. Keep failures and outliers in the record instead of dropping them.
- Report the sample count and the spread, not only the best run.
- Do not conclude that code is faster from how it looks. A faster run that gives a wrong result is not an improvement.
